# Task 001 수동 테스트 체크리스트: 프로젝트 구조 및 라우팅 설정

이 문서는 `docs/ROADMAP.md`의 Task 001(프로젝트 구조 및 라우팅 설정)에서 만든 라우팅·레이아웃 골격을 사람이 브라우저에서 직접 클릭해가며 검증하기 위한 체크리스트다. 이 단계는 UI/데이터/인증 로직이 아직 없는 골격 단계이므로, 여기서는 "올바른 페이지로 라우팅되는가"와 "올바른 레이아웃(하단 내비게이션 / 관리자 사이드바)이 적용되는가"만 검증한다.

## 1. 사전 준비

- [ ] `git status`로 미커밋 변경사항 확인
- [ ] `npm install` (이미 `node_modules`가 있으면 생략 가능)
- [ ] `.env.local` 파일에 `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` 값이 채워져 있는지 확인 > ⚠️ 값이 비어 있으면 `hasEnvVars`가 false가 되어 proxy의 인증 리다이렉트 로직 전체가 스킵된다. 그 경우 **섹션 2(비로그인 상태 테스트)의 기대 결과가 전부 무의미**해지니(모든 경로가 리다이렉트 없이 열림), 먼저 이 값을 확인할 것.
- [ ] `npm run dev` 실행, 터미널에 출력된 실제 URL 확인(기본 `http://localhost:3000`, 사용 중이면 다른 포트로 자동 변경될 수 있음)
- [ ] 브라우저에서 위 URL 접속되는지 확인(서버 정상 기동)
- [ ] 창 2개 준비: **시크릿/게스트 창**(비로그인 테스트용) + **일반 창**(로그인 테스트용) — 쿠키 꼬임 방지를 위해 반드시 분리
- [ ] 일반 창에서 `/auth/login` 접속 → Google 로그인 진행 → 로그인 성공 확인(세션 확보, 이후 섹션 3에서 사용)

## 2. 비로그인 상태 테스트 (시크릿 창)

`lib/supabase/proxy.ts`의 리다이렉트 조건: `pathname`이 `/`가 아니고, 비로그인이고, `/login`으로 시작하지 않고, `/auth`로 시작하지 않으면 → `/auth/login`으로 리다이렉트된다. 즉 예외는 `/`, `/login*`, `/auth/*` 뿐이다.

| #   | 접속 URL               | 기대 결과                         | 비고                                                                                                               | 확인 |
| --- | ---------------------- | --------------------------------- | ------------------------------------------------------------------------------------------------------------------ | ---- |
| 1   | `/`                    | 리다이렉트 없음, 랜딩 페이지 표시 | 유일한 예외 경로                                                                                                   | [ ]  |
| 2   | `/auth/login`          | 리다이렉트 없음, 로그인 폼 표시   | `/auth` prefix 예외                                                                                                | [ ]  |
| 3   | `/events`              | `/auth/login`으로 리다이렉트      |                                                                                                                    | [ ]  |
| 4   | `/events/new`          | `/auth/login`으로 리다이렉트      |                                                                                                                    | [ ]  |
| 5   | `/events/test-id`      | `/auth/login`으로 리다이렉트      | 동적 세그먼트도 동일 적용                                                                                          | [ ]  |
| 6   | `/events/test-id/edit` | `/auth/login`으로 리다이렉트      |                                                                                                                    | [ ]  |
| 7   | `/profile`             | `/auth/login`으로 리다이렉트      |                                                                                                                    | [ ]  |
| 8   | `/join/abc123`         | `/auth/login`으로 리다이렉트      |                                                                                                                    | [ ]  |
| 9   | `/admin/login`         | `/auth/login`으로 리다이렉트      | ⚠️ **알려진 제한사항** — `/login` prefix 체크가 `/admin/login`을 못 잡음(Task 008에서 수정 예정). 버그 리포트 아님 | [ ]  |
| 10  | `/admin/dashboard`     | `/auth/login`으로 리다이렉트      |                                                                                                                    | [ ]  |
| 11  | `/admin/events`        | `/auth/login`으로 리다이렉트      |                                                                                                                    | [ ]  |

| 13  | `/admin/analytics`     | `/auth/login`으로 리다이렉트      |                                                                                                                    | [ ]  |
| 14  | `/protected`           | `/auth/login`으로 리다이렉트      | 기존 Supabase 튜토리얼 페이지, 회귀 확인용                                                                         | [ ]  |
| 15  | `/instruments`         | `/auth/login`으로 리다이렉트      | 기존 페이지, Task 001과 무관하지만 proxy matcher 동일 적용 확인용                                                  | [ ]  |

- [ ] `/join/xyz789` 등 다른 invite_code 값으로도 "초대 링크 참여"가 렌더되는지 확인

## 6. 반응형 뷰포트 확인

`BottomNav`, `AdminSidebar`에는 반응형 breakpoint 클래스가 없어 화면 폭과 무관하게 항상 렌더링된다. 여기서는 "화면 크기별로 숨었다 나타난다"가 아니라 **레이아웃이 겹치거나 깨지지 않는지**만 확인한다.

DevTools 사용법: `F12`(또는 `Ctrl+Shift+I`) → 반응형 모드 전환(`Ctrl+Shift+M`) → 상단에서 폭 직접 입력 또는 프리셋 선택.

| 뷰포트   | 폭     | 확인 페이지        | 확인 항목                                                                     | 확인 |
| -------- | ------ | ------------------ | ----------------------------------------------------------------------------- | ---- |
| 모바일   | 390px  | `/events`          | BottomNav가 화면 하단에 고정, 3개 탭 겹침 없음                                | [ ]  |
| 모바일   | 390px  | `/admin/dashboard` | AdminSidebar(고정 240px)가 좁은 화면에서도 렌더는 됨(눌려 보일 수 있음, 정상) | [ ]  |
| 데스크톱 | 1440px | `/events`          | BottomNav가 본문과 안 겹침(본문 하단 여백으로 가려지지 않음)                  | [ ]  |
| 데스크톱 | 1440px | `/admin/dashboard` | AdminSidebar 좌측 고정, 본문이 남은 영역을 채움                               | [ ]  |

## 7. 알려진 제한사항 (버그 아님 — 실패로 처리하지 말 것)

- [ ] `/admin/login`이 비로그인 상태에서 `/auth/login`으로 리다이렉트되어 실제로 접근 불가능함 — Task 008에서 수정 예정
- [ ] `/admin/*`에 role 기반 권한 체크가 없어 로그인만 하면 어떤 계정으로도 접근 가능 — Task 008에서 구현 예정, 이번 테스트 범위 아님
- [ ] `(main)`, `(dashboard)` 그룹의 새 레이아웃에는 `ThemeSwitcher`(다크모드 토글)나 로그인 상태를 보여주는 헤더가 없음 — 의도된 골격 상태
- [ ] AdminSidebar 하단 "로그아웃"은 클릭 불가능한 정적 텍스트 — 실제 로그아웃 기능 미구현
- [ ] 모든 신규 페이지는 정적 텍스트만 렌더 — 데이터 조회/폼 제출/유효성 검증 없음
- [ ] `BottomNav`/`AdminSidebar`에 반응형 숨김/표시 로직 없음(섹션 6 참조)
